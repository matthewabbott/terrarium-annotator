# 2026-09-29 — Rehydrated-annotator wiki page for Thread 41

## Goal

Generate a steelbea.me-style DokuWiki thread page for Banished Quest
Thread 41 (corpus thread_id 32590433) by rehydrating the 7-thread-lookback
rolling annotator (`data/deepseek-rolling-full-v2.db`, pass
`rolling-full-v2/deepseek-flash`) at the moment it closed Thread 41, then
asking it — in that reconstructed context — to write the page, prompted
with cleaned example pages (40.5, 40, 39.5, story folds omitted).

## Constraints

- Do not disrupt local inference: vLLM serves with `--max-num-seqs 2` and
  both slots are occupied by the two live annotator runs. A third request
  queues server-side; no extra host RAM (client is one HTTP call).
  RAM headroom is ~2GB, so nothing local beyond the HTTP client.
- No future-canon leakage: all glossary/digest state cut at
  `log_seq <= 488` (Thread 41's final batch; seq 483–488).

## Key facts

- Thread 41 = `thread_id 32590433`, story log seq 483–488 (6 batches).
- Pass began 2026-09-27 14:50; the live v2 process started 2026-09-28
  02:39 — a restart happened mid-pass. The window at Thread 41's close is
  therefore NOT a replay from corpus start: it is `_rebuild_window`'s
  7-thread tail at the resume point, replayed forward through 41.
- Run config (run_meta): rolling_window_tokens=200000,
  rolling_trim_target=150000, rolling_min_threads=7,
## Method (final, after user redirection)

User clarified: future-canon knowledge is DESIRABLE for the wiki task
(canonical naming e.g. `characters:skull-kid` vs the 'Burnout' pseudonym;
spoiler-positive Magic/Trivia sections), the Summary/Play-by-Play must
cover only Thread 41, examples = six pages (37–40.5) with the Posts fold
sliced out but the Magic/Characters/Trivia sections BELOW the fold kept,
and total request should stay <300k tokens.

1. Resume points found via duplicate transcript user rows:
   (32389691, batch 2) and (32542209, batch 3) — the latter at
   2026-09-28 12:08 after a recorded ChatClientError, the LAST rebuild
   before Thread 41. `_rebuild_window` loaded the 7 completed threads
   before 40.5; replayed forward from transcript id 2487.
2. Window snapshot chosen: close of Thread 42 (32659843) — spans
   [40.5, 41, 41.5, 42], 154,975 est tokens (chars/4), Thread 41 second
   of four (roughly mid-window). Later closes drop Thread 41's span.
3. Memory state at close of Thread 45.5 (log_seq 542) for extra
   future-informed naming/trivia: digest = cover(96) over seq 0..542
   (tree_version 0, no forgets → summaries are period-authentic);
   glossary = latest revision per entry with log_seq <= 542
   (410 entries, 161,667 chars). Caveat: entry_alias/entry_tag carry no
   log_seq, so tags/aliases are as-of-now.
4. Examples: newsletters (302)–(307), mail headers stripped, `++++ Posts`
   fold cut through its closing `++++`; asserted no qm_post/story_post
   markers remain; all six retain Magic/Characters/Trivia.
5. Payload: reader-v1 system prompt + 93 window messages + one task
   message ≈ 215,700 est tokens (chars/4). temperature 1.0, top_p 0.95,
   chat_template_kwargs {"thinking": false}, max_tokens 8192.
   Sent to http://127.0.0.1:8888/v1/chat/completions (queues behind the
   two live runs; server --max-num-seqs 2, so no preemption, no extra
   host RAM). Script: data/exp/wiki41_send.py; payload:
   data/exp/wiki41_payload.json.

## Result

- Generation succeeded: HTTP 200 after 1010s, 207,940 prompt tokens
  (chars/4 estimate 215,700 — within 4%), 3,291 completion tokens,
  finish=stop. Raw output preserved at `data/exp/wiki-thread-41-raw.txt`
  (plus `wiki41_response.json`, `wiki41_payload.json`).
- **Inference impact**: the request starved in vLLM's waiting queue
  (`reason=capacity`, max-num-seqs=2 both slots held by the annotator
  runs) for ~45 min with no admission. Paused the 5-thread v1 run
  (SIGTERM pid 1677477; checkpoint recorded at thread 38613982 batch 6 —
  crash-safe by design, cf. the 12:08 precedent). Our request was
  admitted immediately. v1 run restarted post-generation with the
  identical command (detached, pid 1767086). RAM untouched (~1.7GB
  available throughout); zero disruption to the v2 run.
- **Fact-check against the corpus caught real drift**: the raw draft
  summarized content from threads 41.5/42 (egg 'confession' + airships,
  national-park forest lore, shotgun, the road/gorge/giant-lizard
  episode, the dream warning, Speed and Confuse effects — all verified
  via term search to appear only in 32599935/32659843, zero hits in
  32590433). The model had threads 40.5–42 in its window and bled
  forward. Corrected surgically against thread 41's 27 story posts
  (dumped to `data/exp/thread41_posts.txt`): replaced displaced
  paragraphs with the actual thread-41 beats (Visitors/Tower device,
  corporations/Red District/lynching Q&A, Sub-City war stories, Darzi
  brooch conversation, Manipulate reading, egg-warming vote), removed
  Speed/Confuse Magic bullets, Dream/Glowing-Face/Lizard trivia, and an
  unverifiable 'SAM's successor-state' claim. Final page (10,432 chars):
  `data/exports/wiki-thread-41.txt`.

## Lessons for the rehydrate-and-ask pattern

0. **Prune-pass experiment** (user request): appended the raw draft as
   an assistant turn + a boundary instruction naming the exact
   `<batch thread=32590433 index=0..5>` cue and the known offenders.
   Second generation (211,711 prompt tokens, 2,798 completion) removed
   every flagged item and produced a better-organized Summary — but
   STILL failed verification: kept the unverified 'skip out or buy
   freedom' clause, re-narrated thread 40.5's four-districts lore as
   thread-41 content, added a `characters:umdnus:king` bullet (40.5
   lore), and drifted the teaser. Conclusion: even with the boundary
   labeled in-context, the model cannot reliably hold it; corpus
   verification is the load-bearing step. Prune draft kept at
   `data/exp/wiki-thread-41-pruned.txt`; the corpus-verified
   `data/exports/wiki-thread-41.txt` remains final.

1. Future knowledge in the window helps naming (skull-kid link landed
   exactly as intended) but the model will silently summarize adjacent
   threads. Mitigation candidates: name the boundary explicitly in the
   task message ("Thread #41 ends at the OOC dice post; the road to the
   Conclave begins in Thread #41.5 — do not include it"), or cut the
   window at the target thread and rely on digest/glossary for future
   knowledge.
2. Resume detection works: duplicate transcript user rows per
   (thread_id, batch_index) mark every rebuild point; replay from the
   last one is deterministic and cheap.
3. A third inference client will starve under max-num-seqs=2; budget a
   pause of one run (SIGTERM is safe; resume is checkpoint-exact) or
   raise max-num-seqs server-side.
